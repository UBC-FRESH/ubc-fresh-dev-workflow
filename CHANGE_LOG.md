- The first CI run on pull request #17 failed in all four jobs. The cause was in the validator, not in the content. It walked the whole working tree, so it scanned untracked files that git ignores. Hypothesis writes a cache under `.hypothesis/`, and that cache holds absolute paths from the machine that ran it. On the runner those paths begin with the runner's home directory, which the personal-path check reports. Nothing in the cache was committed. Local runs passed only because the local paths did not match the check.
- Changed what the validator measures. It now scans the files that git would commit: tracked files, plus untracked files that git does not ignore. It still walks the tree when the directory is not the top level of a repository, which covers generated projects inside `tmp/`, and when git is unavailable or fails. The check itself is unchanged, so every personal path in a file that a commit would include is still an error. Four tests cover the cases: an ignored cache, a new untracked file, a nested directory, and a missing or failed git. `.hypothesis/` is now also ignored explicitly.
